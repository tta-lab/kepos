# Kepos TypeScript Boundary

This document defines where V1 should use TypeScript.

## Decision

New protocol and domain modules should be TypeScript-first.

Platform runtime glue can stay JavaScript until its loader path is proven.

## Why

Kepos V1 has security-sensitive state:

- identity keys
- signed records
- trust grants
- home access policy
- treehole events
- DM requests, invites, threads, and messages
- QR payload schemas

These shapes should be explicit and checked. Plain JavaScript is too easy to drift when several platforms share the same rules.

## Use TypeScript Now

Use TypeScript for pure shared modules under `src/` when they are not directly loaded by a fragile runtime path:

- identity and signed-record helpers
- trust and ContactBook model
- home access policy
- treehole signed event schemas and reducers
- DM request, invite, thread, and message schemas
- QR payload schemas and parsers
- versioned local storage envelopes

Every new TypeScript module must pass:

- `npm run typecheck`
- `npm run compat:typescript` when it is shared protocol logic
- `npm run compat:bundle:typescript` when it must work in the Bare Android backend

## Keep JavaScript For Now

Keep these as JavaScript until their runtime loading path is verified:

- `backend/backend.mjs`
- `desktop/app.tsx`
- `desktop/controller.js`
- `mobile/App.jsx`
- Electron renderer entry code
- Bare worklet entry code
- React Native UI glue

These files should call shared typed modules instead of owning protocol rules.

## Migration Rule

Do not rewrite everything to TypeScript in one pass.

When touching an existing JavaScript protocol/domain module for meaningful new behavior, prefer one of these:

1. Move the changed protocol shape into a new TypeScript module and keep a thin JS caller.
2. Convert the module to TypeScript if all import paths are already proven by tests, Node execution, and Android bundle probes.
3. Leave the file in JavaScript only when the change is small and the module is on a fragile platform path.

The direction is TypeScript for shared rules, JavaScript for platform edges.

## Migration Priority

Convert security-sensitive shared modules before convenience modules.

1. `src/signed-record.ts` (done)
   - core signed envelope, deterministic bytes, key validation, timestamp/version checks
   - everything else depends on this being stable
2. `src/dm-invite.ts` and `src/message-request.ts` (done)
   - DM bootstrap, sealed invite payloads, one-message request rules, signed request validation
   - mistakes here can leak private-message setup through the wrong trust boundary
3. `src/trust-grant.ts` and `src/signed-qr-payload.ts` (done)
   - trust creation, revoke payloads, profile QR, home QR, proof matching
   - this is the normal user-facing authority path
4. `src/contact-book.ts` and `src/dm-thread.ts` (done)
   - durable local trust state, request state, accepted/revoked DM thread state
   - these are central domain models and should become typed before they grow more fields
5. Policy slices from `src/treehole-policy.ts` (done)
   - Autobase/runtime glue can remain JS
   - signed event and writer-policy rules should move behind typed shared helpers

`src/identity.js` already uses the same Ed25519 key shape as signed records. A profile id must be a public key backed by its matching secret key; do not recreate old public-id-only compatibility paths.

## Next Migration Candidates

The next TypeScript work should stay evidence-driven. Current source shape is
roughly `89` JavaScript files, `5` JSX files, `10` MJS files, `23` TypeScript
files, and `2` TSX files after excluding dependencies and generated bundles.
That argues against a broad rewrite. The useful path is to keep moving pure
shared rules and serialized shapes behind typed modules while leaving platform
entrypoints in JavaScript.

High-value candidates:

1. `src/protocol.ts` (done)
   - Why: owns wire-frame type acceptance for chat, treehole controls, message
     requests, DM invites, signed DM fallback, and signed home hello.
   - TS value: gives the room/control frame vocabulary a typed discriminated
     union instead of stringly typed callers.
   - Gate: `test/protocol.test.js`, `test/p2p-room.test.js`,
     `npm run compat:bundle:typescript`, and `npm run backend:bundle:android`.

2. `src/qr-payload.ts`, `src/qr-scan.ts`, and `src/signed-qr-scan.ts` (done)
   - Why: `src/signed-qr-payload.ts` is already typed, but scan/import glue
     still bridges signed payloads into ContactBook and Home join decisions.
   - TS value: makes the normal trust/join path harder to drift across desktop
     and Android.
   - Gate: `test/qr-payload.test.js`, `test/qr-scan.test.js`,
     `test/signed-qr-scan.test.js`, `test/mobile-qr-actions.test.js`, and
     Android bundle checks.

3. `src/home-room.ts`, `src/home-session.ts`, and `src/chat-session.ts` (done)
   - Why: these are pure domain/session shapes for profile-owned homes and
     ephemeral room chat.
   - TS value: locks the owner/address/room-key/session invariants that V1
     relies on before V2 adds room types.
   - Gate: `test/profile-home-trust.test.js`, `test/home-session.test.js`,
     `test/chat-session.test.js`, and the V1 model smoke.

4. `src/treehole-state.js`, `src/treehole-view.js`,
   `src/treehole-snapshot-merge.js`, `src/treehole-storage.js`, and
   `src/treehole-state-publisher.js`
   - Why: signed event creation/reduction is typed, but the rendered snapshot,
     merge, storage path, and publisher helpers still define important runtime
     contracts.
   - TS value: makes cross-device treehole fallback snapshots and app-private
     storage paths explicit.
   - Gate: `test/treehole-state.test.js`, `test/treehole-view.test.js`,
     `test/treehole-snapshot-merge.test.js`, `test/treehole-storage.test.js`,
     `test/treehole-state-publisher.test.js`, and two-device smoke.

5. `src/dm-thread-list.js`, `src/dm-thread-storage.js`,
   `src/dm-session-storage.js`, and `src/dm-session.js`
   - Why: the core DM thread and message records are typed, but thread-list,
     session, and storage envelope helpers still define durable local state.
   - TS value: lowers risk around restart persistence, accepted/revoked thread
     state, and per-profile storage migration.
   - Gate: `test/dm-thread-list.test.js`, `test/dm-thread-storage.test.js`,
     `test/dm-session-storage.test.js`, `test/dm-session.test.js`, and
     `test/v1-model-smoke.test.js`.

6. `src/direct-room-endpoint.js` before `src/direct-room-transport.js`
   - Why: endpoint parsing/formatting is pure and already guards the direct TCP
     path used by cross-device debug smoke.
   - TS value: type the endpoint shape first, then decide later whether the
     transport implementation itself is worth converting.
   - Gate: `test/direct-room-endpoint.test.js`,
     `test/direct-room-transport.test.js`, and two-device smoke.

Worth doing later, but not first:

- `src/identity.js`, `src/local-profile.js`, `src/mobile-profile.js`
  - These are security-sensitive, but they sit close to platform persistence and
    random-source boundaries. Prefer extracting typed envelope validators first
    instead of renaming the whole adapter in one pass.
- Desktop view-model modules such as `src/desktop-*-view-model.js`
  - They are pure and easy to type, but lower risk than protocol/storage. Convert
    them opportunistically when changing UI behavior.
- Desktop command/action modules
  - `src/desktop-command-vocabulary.ts` and
    `src/desktop-command-registry.ts` are already typed. The remaining command
    implementations can stay JS until action payload types are extracted.

Keep as JavaScript for now:

- `backend/backend.mjs`
- `mobile/App.jsx`
- `desktop/controller.js`
- Electron `main.cjs` / `preload.cjs`
- smoke scripts and build scripts
- generated bundles

These are entrypoints or operational glue. They should consume typed helpers
but should not be migrated merely for TypeScript coverage.

## Temporarily Blocked Proof

Final V1 release proof is currently blocked on physical Android availability,
not on a known TypeScript or implementation gap.

The remaining proof is:

- `ANDROID_SERIAL=32131JEHN00865 npm run smoke:two-device:debug`
- `ANDROID_SERIAL=32131JEHN00865 npm run smoke:two-device:debug:pear`
- physical QR helper smoke when a human can aim the phone at the desktop QR

The connected Pixel 7a has repeatedly been switched to other foreground apps
during the smoke run, which invalidates the result. The two-device smoke helper
now reports Android foreground state through `mCurrentFocus` and `mFocusedApp`
so this environment failure is explicit. Do not treat those interrupted runs as
product failures.

## Not V1

V1 does not need:

- a full app-wide TypeScript rewrite
- React Native UI conversion
- Electron renderer conversion
- generated API clients
- runtime schema libraries unless plain TypeScript plus validation helpers becomes too weak
