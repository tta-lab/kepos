# V2 Roadmap

This document records the V2 product direction after V1.

V2 should make the home feel alive by turning self-hosted media and local media
sources into trusted shared rooms. It should connect people who can self-host
with people who care about music, films, books, and shared spaces.

Kepos should not become the media platform. Mature self-hosted products should
own media libraries, metadata, transcoding, subtitles, covers, chapters, and
format-specific playback. Kepos should own trust, invite, shared room state,
local P2P access, presence, revoke, and stop controls.

## Shape

```text
V2A: home/profile/presence/richer chat
V2B: shared music room over NAS or self-hosted music service
V2C: shared reading or audiobook room
V2D: shared watch room over self-hosted video or desktop live stream
```

V2 is not one large feature. It is a sequence of shared media rooms built on the
same home, trust, and local P2P access model.

## V2A: Presence And Richer Home

V2A should polish the social surface:

- profile card
- avatar
- contact detail
- better room presence
- better message UI
- room state that shows who is around
- small multimodal additions only when they support the core loop

The purpose is to make V1 feel like a place, not only protocol plumbing.

## V2B: Shared Music Room

V2B should start with a shared music room over a NAS-backed or self-hosted music
service, preferably a Subsonic-compatible service such as Navidrome.

```text
Navidrome or HTTP music service
  -> Kepos local P2P proxy
  -> trusted listeners
```

The room has one shared queue, one current track, and shared playback state.
Authorized room members can add songs and control playback by default. Every
listener should hear the same track and roughly the same position.

Kepos should keep the room state and playback clock. The self-hosted service
keeps the music library, metadata, artwork, playlists, and stream URLs.

This is not a live singing room, karaoke room, or Kepos-owned music server.
Recording requests can stay in an external table until the listening room is
proven.

## V2C: Reading And Audiobook Rooms

V2C should extend the same shared-room model to reading and audiobooks.

Audiobookshelf is close to the music model: one current item, one queue or
selection, and shared playback state.

Ebook co-reading is different. The shared state is not audio playback. It is:

- book
- chapter
- page or location
- selection
- notes or discussion anchors

Kepos should adapt to the self-hosted product instead of importing books or
building a general ebook server.

## V2D: Watch Room

V2D should support two video source paths.

The first path is self-hosted video:

```text
Jellyfin, Plex, or Emby
  -> Kepos local P2P proxy
  -> trusted viewer playback
```

This is the right path when the film or show already exists in a self-hosted
library.

The second path is a desktop live stream:

```text
OBS or compatible producer
  -> localhost ingest
  -> Kepos P2P media stream
  -> trusted viewer playback
```

This is needed for content that is hard to download, hard to record, not
already in the library, or better shared as a live desktop session. OBS handles
capture, scene composition, system audio, mic choice, and encoding. Kepos
handles trust, invite, P2P delivery, room lifecycle, and stop controls.

V2D is not a meeting product. The first version does not include cameras, viewer
microphones, multi-viewer conferencing, recording, or SFU.

## Why This Order

V2A improves the room surface.

V2B proves the shared self-hosted media room model:

- local P2P access to an owner-hosted media service
- shared queue and playback state
- trusted join and revoke
- rough sync without Kepos owning the music library

V2C extends the model to books and audiobooks.

V2D extends the model to video. It should support self-hosted video first where
possible, while preserving an OBS-compatible desktop stream path for media that
cannot be cleanly downloaded, recorded, or served from a library.

The user-facing path is:

```text
V1: private home works
V2A: the home feels inhabited
V2B: friends can listen together from a self-hosted music library
V2C: friends can read or listen to audiobooks together
V2D: friends can watch together from a library or desktop stream
```

## Boundaries

V2 should not:

- expand into public rooms
- add public discovery
- add usernames
- become a video meeting clone
- build a general streaming platform
- become a NAS permission system
- become a media transcoder
- rebuild Navidrome, Jellyfin, Plex, Emby, Audiobookshelf, or Kavita

The rule is:

```text
one trusted home, one explicit media source, shared room state, clear stop button
```
