# V1 MLP UI Stack: Tailwind And daisyUI

This document records the V1 MLP UI stack decision after choosing a desktop
React renderer.

## Decision

Use:

```text
React
TailwindCSS
daisyUI
lucide-react
```

for the desktop V1 MLP renderer.

Use daisyUI as a product-speed component engine, not as the final Kepos brand.

This has been checked against the current official daisyUI v5 docs:

- daisyUI v5 is a TailwindCSS v4 CSS-first plugin.
- The plugin and theme config should live in CSS using `@plugin "daisyui"`
  and `@plugin "daisyui/theme"`.
- Custom themes use daisyUI semantic variables such as
  `--color-base-100`, `--color-primary`, `--color-success`,
  `--radius-field`, and `--radius-box`.
- The official daisyUI Codex skill is installed project-locally under
  `.agents/skills/daisyui`; future Tailwind/daisy JSX work should read that
  skill before changing UI code.

## Why TailwindCSS

TailwindCSS fits the desktop React rewrite because Kepos needs:

- stable app-shell layout
- responsive desktop and mobile-like preview states
- fast iteration on spacing, density, and states
- local design tokens
- component-level style control without inventing a CSS architecture first

Tailwind should carry layout and low-level styling.

## Why daisyUI

daisyUI is worth using because Kepos needs to move from protocol console to
minimum lovable product quickly.

Useful parts:

- buttons
- modals
- tabs
- drawers
- menus
- toggles
- badges
- alerts
- theme switching

The theme system is especially relevant. Kepos may want several young-feeling
visual modes:

```text
Neo Cozy
Indie Console
Soft Brutalist
```

daisyUI makes it cheap to test these without rewriting component structure.

## Constraint

Do not let screens depend directly on raw daisyUI everywhere.

Prefer Kepos component wrappers:

```text
Button
IconButton
Modal
Tabs
StatusPill
MessageBubble
PersonCard
TrustCard
QrDialog
TreeholePost
Composer
EmptyState
```

Those components may use daisyUI classes internally:

```text
btn
btn-primary
modal
tabs
badge
alert
drawer
```

Screens should read like Kepos product code, not like a daisyUI demo.

Implementation rule for the current migration:

- Keep stable Kepos product class names such as `pane`, `composer`,
  `contextGroup`, `peopleEmpty`, and `railButton` because tests, smoke hooks,
  and product language depend on them.
- Add daisyUI/Tailwind classes where they improve real component behavior:
  `btn`, `badge`, `card`, `input`, `textarea`, `collapse`, `alert`, semantic
  `base-*` colors, and responsive layout utilities.
- Prefer wrapping daisyUI inside shared components like `ActionButton`,
  `PaneHeader`, `PanelHeader`, and `RequestActionButton`.
- Do not port React Native mobile screens to web Tailwind classes. Mobile
  should mirror the same visual tokens and component decisions through native
  styles.

## Default Theme Direction

The selected default theme pair is:

```text
Light: Neo Cozy
Dark: Indie Console
```

Light mode should feel like a warm private room. Dark mode should feel like a
small indie lobby that can grow into V2/V3 live rooms and game rooms.

Quiet Cyber is not part of the V1 MLP visual direction. Do not keep it as a
parallel theme candidate while designing the main product UI.

Reason:

- Kepos is first a private home for trusted friends, not a security console.
- V1 needs warmth and daily-use comfort before power-user tunnel energy.
- V2 listening/watch rooms and V3 game rooms need a room/lobby language that
  grows naturally from chat.

Both themes should feel young through private-hangout energy, not through dark
network-tool styling.

### Default Theme Traits

The V1 theme pair should use:

- warm surfaces and soft contrast
- playful but restrained badges
- room/lobby language instead of server/channel language
- stable left-rail and bottom-tab navigation that feels slightly console-like
- clear session cards for future listening, watch, and game rooms
- friendly trust states that do not look like enterprise security UI

### Neo Cozy Responsibilities

Neo Cozy provides the light theme:

- warm background surfaces
- human spacing
- readable chat and treehole content
- friendly empty states
- trust actions that feel personal

This is the daytime "home" face of Kepos.

### Indie Console Responsibilities

Indie Console provides the dark theme:

- left rail and room tabs that feel like a lobby
- compact status pills for live sessions
- playful but restrained badges
- clear invite/join/start-room actions
- enough game-room energy for V3 without making V1 look game-only

This is the nighttime "live room" face of Kepos.

## Non-Goals

This decision does not mean:

- adopting generic daisyUI screenshots as Kepos brand
- using every daisyUI component
- exposing theme switching as a major V1 feature
- making the app look like a dashboard
- replacing lucide icons
- avoiding custom CSS when a component needs stronger identity

## Risks

### Generic Component Feel

daisyUI can make the app look like many other Tailwind prototypes.

Mitigation: define Kepos wrappers and custom themes early.

### Too Many Themes

Theme switching can become a distraction.

Mitigation: V1 ships one default theme. Other themes are design probes until
there is a product reason to expose them.

### Component Lock-In

If business screens use raw daisyUI classes everywhere, changing style later
becomes harder.

Mitigation: keep raw daisyUI inside shared UI components.

## Recommendation

Use TailwindCSS and daisyUI for the V1 MLP React renderer.

The practical rule is:

```text
Tailwind for layout
daisyUI for fast primitives and theming
Kepos components for product language
lucide for action icons
custom themes for identity
```

This is the fastest path to a young-feeling UI without giving up future visual
control.
