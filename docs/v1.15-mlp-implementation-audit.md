# V1 MLP Implementation Audit

This audit records the current V1 MLP state after the React desktop shell and
mobile UX polish passes.

## Verdict

V1 is close on product UX and shared domain behavior. It is not yet complete as
an architecture target because the desktop P2P/backend runtime still lives in
the renderer controller instead of a Bare worker bridge.

## Product UX Status

Current evidence says the normal V1 loop no longer depends on raw keys as the
primary user path:

- desktop has Home, Direct, Treehole, and People navigation
- mobile has Home, Direct, Treehole, and People tabs
- Profile QR and Home QR are the normal trust and join surfaces
- manual home keys and manual DM recipient ids stay in Advanced
- desktop and mobile use product words for Home, People, Direct messages, and
  Treehole
- desktop and mobile expose empty, disabled, and short error states for the main
  V1 surfaces
- desktop and mobile Direct guide zero-contact users toward People/trust instead
  of the manual recipient debug path
- mobile QR scanner has cancel and permission-denied states
- desktop large QR dialogs are keyboard reachable

Primary evidence:

- `test/desktop-mlp-shell.test.js`
- `test/two-device-smoke-hooks.test.js`
- `test/manual-key-debug-ui.test.js`
- `docs/v1.12-mlp-ux-after-architecture-switch.md`

## Shared Model Status

The shared V1 model is substantially complete:

- one device is one profile
- profile id is the identity public key
- one profile owns one home
- ContactBook is the local trust state
- signed Profile QR creates trust
- signed Home QR checks trusted-only access
- treehole signed mode enforces owner main posts and trusted interactions
- message requests are bounded and do not grant home access
- accepted requests create durable pairwise DM threads
- signed DM bodies use dedicated pairwise replication channels
- revoke updates trust, treehole policy, DM thread state, and active DM runtime

Primary evidence:

- `test/v1-model-smoke.test.js`
- `test/contact-book.test.js`
- `test/signed-qr-scan.test.js`
- `test/treehole-signed-events.test.js`
- `test/dm-thread-runtime.test.js`
- `test/revoke-state.test.js`
- `docs/v1.07-architecture-gaps.md`

## Runtime Evidence Status

Automated and manual evidence currently covers:

- desktop smoke wiring
- desktop contact persistence smoke
- Android bundle and native-library checks
- Android scanner open/cancel smoke
- debug two-device desktop/Android transport smoke
- manual physical desktop-to-Android Profile QR and Home QR scan path

This is enough to keep iterating, but it is not the same as completing the
desktop worker architecture.

## Remaining Required Work

### 1. Desktop Bare Worker Bridge

Status: incomplete.

`docs/v1.11-mlp-desktop-react-architecture.md` says desktop should become:

```text
Electron renderer React UI
  -> preload/main bridge
  -> Bare worker
  -> Hyperswarm / Corestore / Autobase / DM / Treehole
```

Current implementation has started splitting the renderer controller into
worker-shaped runtime boundaries:

- `src/desktop-dm-runtime.js` owns desktop Direct Message session state, message
  request creation, invite acceptance, thread runtime lifecycle, and DM message
  and thread storage
- `src/desktop-home-runtime.js` owns desktop Home transport, P2P room lifecycle,
  chat session updates, and signed Home hello handling
- `src/desktop-treehole-runtime.js` owns desktop Treehole lifecycle,
  replication, state publishing, bootstrap sharing, and writer grants
- `src/desktop-backend-runtime.js` composes those three runtime modules behind
  one renderer-local backend facade and forwards runtime updates through the
  desktop backend event vocabulary
- `src/desktop-backend-subscriptions.js` owns renderer-side backend event
  subscriptions for Home and Direct Message sessions, Treehole snapshots, peer
  counts, and backend errors
- `desktop/controller.js` now installs those subscriptions through one module
  instead of wiring every backend event inline. This is still renderer-local
  today, but it matches the preload/main/Bare event shape.
- `src/desktop-home-join-service.js` owns DOM-free Home join preparation for
  owned homes, manual keys, signed Home QR join details, and treehole policy
  snapshots
- `src/desktop-qr-service.js` owns DOM-free desktop Profile QR trust handling,
  Home QR join validation, and signed share QR URI/SVG generation
- `src/desktop-revoke-service.js` owns DOM-free desktop contact revoke
  orchestration across ContactBook, DM thread state, treehole policy, and
  recipient-selection cleanup intent
- `src/desktop-message-request-service.js` owns DOM-free desktop message request
  accept/ignore orchestration across ContactBook updates, DM invite broadcasts,
  and local DM request dismissal intent
- `src/desktop-control-service.js` owns DOM-free Home control handling for
  message requests, DM invites, and Treehole bootstrap/writer grants, including
  ContactBook updates, incoming request append intent, accepted invite
  transitions, Treehole open intent, writer grant intent, and outbound Treehole
  send intent
- `src/desktop-home-chat-view-model.js` owns snapshot-shaped display data for
  desktop Home chat rows, including incoming/outgoing classes, sender labels,
  and text
- `desktop/app.jsx` now renders Home chat rows in React through
  `globalThis.keposDesktopUi.setHomeMessages()`. `src/desktop-render-presenter.js`
  now pushes the Home chat snapshot, and the controller no longer mutates the
  Home chat list DOM.
- `src/desktop-people-view-model.js` owns snapshot-shaped display data for
  desktop People trusted contacts and message requests, including labels,
  previews, and accept/revoke/ignore payloads
- `desktop/app.jsx` now renders People trusted contacts and message requests in
  React through `globalThis.keposDesktopUi.setPeople()` and receives
  accept/ignore/revoke callbacks through `setPeopleActions()`.
  `src/desktop-render-presenter.js` now pushes the People snapshot, and the
  controller no longer mutates the People list DOM.
- `src/desktop-direct-view-model.js` owns snapshot-shaped display data for
  desktop Direct message rows, including incoming/outgoing classes, meta labels,
  message request copy, and accept/ignore payloads
- `desktop/app.jsx` now renders Direct message rows in React through
  `globalThis.keposDesktopUi.setDirectMessages()` and receives accept/ignore
  callbacks through `setDirectMessageActions()`. `src/desktop-render-presenter.js`
  now pushes the Direct message snapshot, and the controller no longer mutates
  the Direct message list DOM.
- `src/desktop-direct-contact-picker-view-model.js` owns snapshot-shaped display
  data for the desktop Direct message trusted-contact picker, including selected
  state and the zero-contact empty state.
- `desktop/app.jsx` now renders the Direct message trusted-contact picker in
  React through `globalThis.keposDesktopUi.setDirectContactPicker()` and receives
  select/open-People callbacks through `setDirectContactPickerActions()`.
  `src/desktop-render-presenter.js` now pushes the picker snapshot; the
  controller still keeps a plain selected-recipient id for selection and revoke
  cleanup, but it no longer mutates the contact picker DOM.
- `src/desktop-treehole-view-model.js` owns snapshot-shaped display data for
  desktop Treehole post/comment rows, including author labels, time labels,
  stats, nested comments, and like/comment payloads
- `desktop/app.jsx` now renders Treehole post/comment rows in React through
  `globalThis.keposDesktopUi.setTreeholePosts()` and receives like/comment
  callbacks through `setTreeholeActions()`. Inline comment and main post draft
  state now live in React; the controller still owns Treehole runtime calls.
- `src/desktop-status-view-model.js` owns snapshot-shaped display data for
  desktop status, notice, advanced home/profile ids, peer count, Treehole status,
  and raw error detail.
- `desktop/app.jsx` now renders these status labels in React through
  `globalThis.keposDesktopUi.setStatus()`. `src/desktop-render-presenter.js`
  now pushes the status snapshot, and the controller no longer mutates the
  status label DOM.
- `desktop/app.jsx` now renders the large QR dialog through
  `globalThis.keposDesktopUi.setLargeQr()` and closes it from React button,
  overlay, and Escape handlers. `src/desktop-qr-actions.js` owns open/close
  state transitions and focus restoration, and the controller no longer mutates
  or listens to the dialog DOM.
- `desktop/app.jsx` now renders the inline profile/home share QR outputs through
  `globalThis.keposDesktopUi.setShareQrOutputs()`. `src/desktop-qr-actions.js`
  creates signed payloads, and the controller no longer writes QR SVGs or
  read-only URI details into DOM nodes.
- `desktop/app.jsx` now renders the context-panel forms through
  `globalThis.keposDesktopUi.setContextFormActions()` and
  `setContextFormDraft()`. Display name, manual home key, Home QR paste, Profile
  QR paste, and trust alias are React-controlled. The controller still owns Home
  join, QR trust, QR copy, and large-QR command execution, but it no longer
  reads, listens to, or clears those form DOM nodes.
- `desktop/app.jsx` now renders desktop rail active state and pane visibility
  through `globalThis.keposDesktopUi.setActiveTab()`. The controller still owns
  the tab transition command, but React handles tab clicks and renders pane/tab
  classes and `aria-current`.
- `desktop/app.jsx` now owns shell actions and busy state through
  `globalThis.keposDesktopUi.setShellActions()` and `setShellBusy()`. React
  handles rail tab clicks, the leave-home button, large QR close/overlay/Escape
  behavior, and `body[aria-busy]`. The controller still dispatches commands and
  restores large QR focus, but it no longer queries shell buttons or dialog DOM
  nodes directly.
- `desktop/app.jsx` now renders action and composer disabled state through
  `globalThis.keposDesktopUi.setControls()`. `src/desktop-render-presenter.js`
  now calculates availability from runtime state and form inputs, and the
  controller no longer mutates button disabled flags or Treehole composer
  disabled DOM state directly.
- `desktop/app.jsx` now owns the Home chat composer draft and submit flow through
  `globalThis.keposDesktopUi.setHomeComposerActions()`. Home message production
  now lives in `src/desktop-message-actions.js`, and the controller no longer
  reads or clears the Home chat input DOM.
- `desktop/app.jsx` now owns the Direct message composer draft, selected
  recipient, advanced manual recipient input, and submit flow through
  `globalThis.keposDesktopUi.setDirectComposerActions()`. Direct message and
  request send actions now live in `src/desktop-message-actions.js`; the
  controller no longer reads, listens to, or clears Direct message input DOM.
- `desktop/app.jsx` now owns the Treehole main post composer draft and submit
  flow through `globalThis.keposDesktopUi.setTreeholeComposerActions()`.
  Treehole post/comment/like actions now live in
  `src/desktop-message-actions.js`, and the controller no longer reads or clears
  the Treehole input DOM.
- `src/desktop-renderer-backend-client.js` is now the renderer command/event
  client. `desktop/controller.js` dispatches commands and subscribes to backend
  events through this client instead of directly coupling UI code to the local
  bridge variable.
- `src/desktop-command-dispatcher.js` now owns renderer-side command dispatch,
  blocking-command pending state, and dispatch error forwarding. The controller
  still calls `dispatchCommand()`, but the pending lock and backend dispatch
  mechanics are no longer implemented inline.
- `src/desktop-command-host.js` is now the desktop command host. It owns V1
  command-to-action mapping and payload normalization before dispatch reaches
  the action implementations. `desktop/controller.js` still supplies those
  actions for now, but it no longer builds the command registry inline.
- `src/desktop-backend-actions.js` now composes the concrete V1 backend command
  action map from the message, room, trust, and message-request action groups.
  `desktop/controller.js` still creates those groups, but it no longer inlines
  the command action table passed to the backend host.
- `src/desktop-message-request-actions.js` now owns pending DM request
  accept/ignore action implementations. `desktop/controller.js` still wires
  runtime getters, profile context, notice updates, and render hooks, but
  request behavior is no longer implemented inline in the controller.
- `src/desktop-room-actions.js` now owns Home create/join/QR-join/leave action
  implementations. `desktop/controller.js` still wires runtime getters/setters,
  profile/context helpers, form draft updates, and render hooks, but room
  lifecycle behavior is no longer implemented inline in the controller.
- `src/desktop-trust-actions.js` now owns Profile QR trust and contact revoke
  action implementations. `desktop/controller.js` still wires runtime getters,
  profile context, selected-recipient setters, notice updates, and render hooks,
  but trust/revoke behavior is no longer implemented inline in the controller.
- `src/desktop-qr-actions.js` now owns share QR generation, large QR
  open/close/focus restoration, and copy-to-clipboard notice behavior.
  `desktop/controller.js` still wires profile context, clipboard/write UI hooks,
  notice updates, and render hooks, but QR behavior is no longer implemented
  inline in the controller.
- `src/desktop-control-actions.js` now owns inbound control-frame handling for
  message requests, DM invites, treehole bootstrap, treehole writer grants, and
  outbound treehole bootstrap/writer control sends. `desktop/controller.js`
  still wires runtime getters/setters, profile context, notice updates, and
  render hooks, but control-frame behavior is no longer implemented inline in
  the controller.
- `src/desktop-local-backend-host.js` is now the renderer-local backend host. It
  composes the command host, backend bridge, backend runtime facade, and event
  forwarding. `desktop/controller.js` still supplies action implementations and
  the remaining control-frame callbacks, but it no longer wires those backend
  pieces directly.
- `src/desktop-message-actions.js` owns Home chat send, Direct message
  send/request, and Treehole post/comment/like action implementations. This is
  the first slice of active command action implementation moved out of
  `desktop/controller.js`.
- Home chat, Direct message, and Treehole composer commands now receive explicit
  payloads from the renderer. Those handlers no longer read composer text from
  DOM fields, which is required before moving command handlers behind
  preload/main/Bare.
- Home QR join, manual Home join, Profile QR trust, QR copy, and large-QR actions
  now receive explicit renderer payloads or callbacks. The handlers still run in
  the renderer for now, but their command inputs are no longer hidden DOM reads.
- `src/desktop-profile-context.js` centralizes desktop profile and ContactBook
  access. `desktop/controller.js` no longer imports the low-level local adapter
  functions directly.
- `src/desktop-storage-base.js` and Electron main/preload wiring expose
  `<Electron userData>/kepos/v1` to the renderer. The desktop backend runtime
  now passes that base path to Treehole, and Treehole uses the shared
  `createTreeholeStoragePath()` helper.
- `desktop/electron/preload.cjs` and `desktop/electron/backend-ipc.cjs` provide
  the first Electron preload/main IPC bridge skeleton for backend
  dispatch/subscribe traffic. The registered bridge is fail-closed by default
  and now has a `connectBackend()` door for wiring real backend dispatch without
  rebuilding the IPC channel.
- `desktop/controller.js` still imports ContactBook read helpers directly, but
  it no longer owns signed share QR rendering, incoming message request
  ContactBook mutation, or incoming DM invite acceptance
- `desktop/controller.js` still wires join/trust/revoke/control action
  implementations, and the renderer backend client still defaults to the local
  bridge because `window.keposBackend` is not yet backed by a real main/Bare
  runtime
- Electron running with `nodeIntegration: true` and `contextIsolation: false`
- React renderer importing `./controller.js` after render

This means the UI is product-shaped, but the desktop runtime boundary is still
only partly separated. It is not yet the target Bare worker bridge.

Next phase:

1. Move the Home, Direct Message, and Treehole runtime modules behind the actual
   preload/main/Bare worker bridge.
2. Keep renderer state as snapshots and form drafts only.
3. Preserve current desktop smoke behavior through the bridge.
4. Only after the bridge works, tighten Electron renderer isolation.

Do not mix this with new UX work.

### 2. Desktop Dynamic Lists Are React-Owned

Status: done for the main dynamic list surfaces.

React owns the stable desktop shell, Home chat list, Direct message list, Direct
message trusted-contact picker, People lists, Treehole post/comment rows, and
desktop status labels, plus the large QR dialog, inline share QR outputs, and
rail/pane active state, action/composer disabled state, and the Home chat,
Direct message, Treehole main post, and context-panel form drafts.

Home chat rows, People contacts/message requests, Direct message rows, Direct
message trusted-contact picker rows, Treehole post/comment rows, and status
labels now have separate view-model boundaries in
`src/desktop-home-chat-view-model.js`, `src/desktop-people-view-model.js`,
`src/desktop-direct-view-model.js`,
`src/desktop-direct-contact-picker-view-model.js`, and
`src/desktop-treehole-view-model.js`, and `src/desktop-status-view-model.js`.
These surfaces feed React components through the renderer UI bridge.

This is still not the final desktop architecture, but the remaining work is no
longer mainly UI DOM migration. Repeated content, status, navigation, QR
display, shell actions, busy state, disabled-state, Home chat draft, Direct
message draft/recipient, Treehole main post draft, and context-panel form draft
surfaces no longer require imperative DOM construction.

The current React shell has first-pass MLP polish for theme, focus, hover,
navigation, and narrow-screen layout. That improves the product surface, but it
does not change the architecture status: renderer state ownership is still
split between React and the imperative controller.

Next phase:

- move the desktop runtime behind the preload/main/Bare worker bridge
- keep React fed by snapshots, drafts, and explicit command payloads
- do visual polish on top of this ownership boundary instead of adding
  controller DOM listeners back

### 3. Live Cross-Device Proof Remains Debug-Heavy

Status: acceptable for iteration, not final proof.

The debug two-device smoke proves live transport behavior, but part of the path
uses debug setup rather than the fully normal physical QR flow. Manual physical
QR evidence covers the screen-to-camera Profile QR and Home QR path.

Next phase:

- keep manual smoke for final V1 readiness
- avoid making smoke work the main implementation thread until the user wants
  release proof

## Non-Blocking For V1

These are not V1 blockers:

- desktop camera scan
- key rotation after revoke
- compact binary QR payloads
- multi-device identity
- safety-number compare UX
- V2 listening/watch room features
- V3 RetroArch or local service tunnels

## Next Best Work

The next implementation phase should be the desktop backend bridge, not more
surface polish. The UI polish pass has removed the most obvious MLP blockers;
continuing to polish without separating the runtime would avoid the largest
remaining V1 architecture requirement.
