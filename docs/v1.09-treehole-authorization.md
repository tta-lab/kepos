# Kepos Treehole Authorization

This document defines how V1 should authorize treehole reads and writes.

## Decision

V1 product treehole writes must use signed events.

Autobase writer access is a transport/write capability. It is not the authorization SSOT. The authorization SSOT is owner identity plus ContactBook trust.

## Current Prototype State

Current code:

- `src/treehole-base.js` defaults to unsigned JSON prototype events for compatibility.
- `src/treehole-base.js` also supports `mode: 'signed'`, which appends signed product treehole events to Autobase.
- `src/treehole-state.ts` reduces post, comment, and like events without signature checks.
- `src/treehole-signed-events.ts` reduces signed product events with signature and trust-policy checks.
- signed mode uses owner-signed `treehole.writer.grant.v1` events to add Autobase writer keys.
- unsigned prototype mode still uses `treehole.writer.add` for debug compatibility.
- In unsigned prototype mode, a replicated writer can create a main post.
- In signed mode, a replicated non-owner writer's main post is ignored by the reducer.
- In signed mode, legacy unsigned `treehole.writer.add` grants are ignored.

Unsigned mode is acceptable only as prototype plumbing. It is not V1 product authorization.

## V1 Rules

Treehole belongs to one owner profile.

Rules:

- owner can create main posts
- owner can tombstone own main posts
- trusted users can read
- trusted users can comment
- trusted users can like/unlike
- trusted users cannot create main posts in someone else's treehole
- comment author can tombstone own comment
- treehole owner can hide/tombstone any comment in their treehole
- pending message request grants no treehole access
- public home does not imply treehole read

## Signed Event Envelope

Every product treehole event should use the shared signed-record envelope.

```js
SignedRecord {
  type,
  version,
  payload,
  signerProfileId,
  createdAt,
  signature
}
```

The signed bytes should use fixed `compact-encoding` schemas, not ad hoc `JSON.stringify()`.

## Event Payloads

### Post Create

```js
TreeholePostCreate {
  treeholeOwnerProfileId,
  postId,
  authorProfileId,
  authorDisplayName?,
  text,
  createdAt
}
```

Authorization:

- signature verifies against `authorProfileId`
- `authorProfileId === treeholeOwnerProfileId`
- text is non-empty
- duplicate `postId` is ignored

### Post Tombstone

```js
TreeholePostTombstone {
  treeholeOwnerProfileId,
  postId,
  actorProfileId,
  createdAt
}
```

Authorization:

- signature verifies against `actorProfileId`
- `actorProfileId === treeholeOwnerProfileId`
- post exists

Effect:

- hide post in normal UI
- hide comments and likes under that post in normal UI
- do not claim secure erasure

### Comment Create

```js
TreeholeCommentCreate {
  treeholeOwnerProfileId,
  postId,
  commentId,
  authorProfileId,
  authorDisplayName?,
  text,
  createdAt
}
```

Authorization:

- signature verifies against `authorProfileId`
- post exists and is not tombstoned
- owner ContactBook/trust policy says `authorProfileId` can comment
- duplicate `commentId` is ignored

### Comment Tombstone

```js
TreeholeCommentTombstone {
  treeholeOwnerProfileId,
  postId,
  commentId,
  actorProfileId,
  createdAt
}
```

Authorization:

- signature verifies against `actorProfileId`
- comment exists
- `actorProfileId` is the comment author or `treeholeOwnerProfileId`

Effect:

- hide comment in normal UI
- keep tombstone in the append-only log

### Like Add / Remove

```js
TreeholeLike {
  treeholeOwnerProfileId,
  postId,
  actorProfileId,
  createdAt
}
```

Authorization:

- signature verifies against `actorProfileId`
- post exists and is not tombstoned
- owner ContactBook/trust policy says `actorProfileId` can like

Reducer behavior:

- `like.add` marks active like for `actorProfileId`
- `like.remove` clears active like for `actorProfileId`
- final like count is active likes, not raw event count
- duplicate/out-of-order events collapse by actor and event order

## Writer Grants

Autobase requires writers for replicated writes, but writer grants should not decide product authorization alone.

V1 should use lazy writer authorization:

1. B is trusted by A.
2. B tries to comment or like A's treehole.
3. A verifies B is trusted.
4. A grants B Autobase writer access if needed.
5. B appends a signed comment/like event.
6. Reducer verifies signature and policy before applying the event.

Non-owner writer access must not allow main posts because reducer policy rejects signed post-create events where `authorProfileId !== treeholeOwnerProfileId`.

## Trust Snapshot

Reducer authorization needs a policy input.

The reducer should not read platform storage directly. It should receive or be configured with a trust policy snapshot for the treehole owner.

Target shape:

```js
TreeholePolicy {
  ownerProfileId,
  trustedProfileIds,
  revokedProfileIds
}
```

Policy behavior:

- owner is always allowed to write owner actions
- trusted and not revoked can comment/like
- revoked cannot comment/like even if they still have an old writer key
- unknown cannot read/write trusted-only treehole

## Unauthorized Events

Unauthorized, malformed, duplicate, or unverifiable events should be ignored by the reducer.

The reducer should not throw for remote bad events during normal replication. It should return state from valid events only.

Debug tooling may expose ignored event counts later, but normal UI should not show raw invalid events.

## UI Semantics

Normal UI:

- hides tombstoned posts
- hides tombstoned comments
- renders author alias from local ContactBook first
- falls back to signed profile metadata later
- falls back to event display-name snapshot or shortened profile id

Normal UI should not show forum-style "deleted comment" placeholders in V1.

## Implementation Order

1. Add shared signed-record utilities and compact-encoding schemas.
2. Add treehole signed event constructors.
3. Add reducer policy input.
4. Make reducer ignore unsigned product events unless explicitly running prototype/debug mode.
5. Add post/comment/like/tombstone tests.
6. Update Autobase append paths to write signed events.
7. Update writer grant path to be lazy and trust-gated.
8. Keep existing unsigned behavior only behind named prototype/debug compatibility if needed during migration.

Current status:

- signed event constructors and reducer policy exist in `src/treehole-signed-events.ts`
- focused tests exist in `test/treehole-signed-events.test.js`
- `src/treehole-base.js` supports signed product mode for post, comment, like/unlike, post tombstone, and comment tombstone append paths
- `src/treehole-policy.ts` centralizes signed/prototype treehole session option selection
- `canGrantTreeholeWriter()` gates Autobase writer grants by owner profile id and trusted/revoked policy snapshot
- signed-mode writer grants are recorded as owner-signed `treehole.writer.grant.v1` events that bind writer profile id to Autobase writer key
- `src/treehole-view.ts` serializes reducer state into UI/RPC posts with embedded comments
- `test/treehole-base.test.js` covers signed Autobase owner posts, trusted comment/like writes, non-owner post rejection, owner comment deletion, signed writer grants, and unsigned writer grant rejection
- desktop and Android UI expose text post, comment, and like controls backed by signed treehole events when signed mode is active
- desktop and Android callers pass identity, owner profile data, and local ContactBook-derived treehole policy through the shared session helper
- desktop and Android writer control handling includes writer profile id and checks the local policy before adding a writer
- unsigned prototype mode remains available for debug and incomplete identity contexts
