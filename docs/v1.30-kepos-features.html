Kepos / V1 MLP

可信小圈子的私人花园。

Kepos 当前 V1 聚焦一个简单路径：Profile QR 加好友，Contacts 管理信任，Messages 持久私聊，显式进入好友 Home，再看 Recent posts 或写 My treehole。底层仍是 P2P，但正常用户不需要理解原始 key 或 topic。

当前能力

2+ 主产品端
QR 好友请求入口
IM 消息与动态

这是当前 V1 MLP 功能说明页，不是发布页。最终 ready 仍需要真实 desktop/Android normal path release proof。

已有功能

第一版聚焦私人 IM 的闭环：朋友关系、持久消息、个人动态、显式 Home 进入和撤销信任。 Home QR 和手动 key 仍可用于 Advanced/debug，不是正常授权入口。

profile

Profile QR 好友请求

扫描或粘贴 Profile QR 会准备好友请求，而不是直接创建信任。接受请求后双方进入 Contacts，并获得后续 Messages 和 Home 入口。

messages

持久 Messages

Messages 有线程列表、请求行、未读标记、联系人头像和重启恢复。消息体走独立的 pairwise 通道，不混进 Home room chat。

contacts

Contacts 和撤销

Contacts 显示好友请求、已发送请求、可信好友和 removed/ignored 状态。撤销会阻止未来访问， 但不会承诺删除对方已经复制到本地的数据。

home

显式进入 Home

朋友关系是权限，signed Home descriptor 是连接信息。用户从可信联系人 profile 显式 Enter Home，未信任用户不能读取私有 treehole 内容。

treehole

My treehole / Recent posts

My treehole 是自己的持久动态面。可信联系人 profile 可显示 Recent posts，并通过 Home bootstrap 和本地缓存刷新。

evidence

类型和证据门禁

npm run v1:gate 覆盖 lint、typecheck、Node tests、TypeScript probes、 desktop bundle、Android Bare bundle、Expo export 和 APK native-library 检查。

支持的端

当前主产品目标是 desktop 和 Android 的同一套 V1 IM 流程；CLI 保留为协议验证入口。

Android

React Native + Bare 后端

Expo React Native + react-native-bare-kit。支持 Profile QR、Contacts、 Messages、Home、My treehole、scanner 打开/取消和 app-private 持久化。

Desktop

Electron + pear-runtime

Electron React UI + pear-runtime bundled Bare worker。Pear smoke 已覆盖 Home、Profile QR、ContactBook、message request、restart 和 revoke 路径。

CLI

终端房间原型

命令行端仍可创建/加入房间并发送实时文字消息，适合快速验证协议和 P2P 连接。

iOS

暂未接入

当前没有 iOS 构建路径。后续如果做移动双端，需要单独验证 Bare/iOS 集成和 native module 链接。

Web

暂不支持

当前 P2P 栈依赖 native/Bare 能力，浏览器 Web 端不是第一阶段目标。

Server

没有业务服务器

Kepos 当前不是 client-server 产品；已有后端是本地 Bare worker/worklet，不是中心化服务。

运行入口

  • npm run desktop
  • npm run android
  • npm run v1:gate
  • npm run smoke:desktop:pear
  • npm run smoke:android

还需要证明 / 非 V1

  • 最终 V1 ready 需要真实 desktop/Android normal path release proof。
  • Debug two-device smoke 和 physical QR 是强子证据，但不能替代完整 friend-request 流。
  • iOS、Web、正式发布和 OTA 不属于当前 V1。
  • V2 才考虑听歌房、观影房和更丰富媒体。
  • V3 才考虑本地服务 tunnel 和 RetroArch 游戏联机。
